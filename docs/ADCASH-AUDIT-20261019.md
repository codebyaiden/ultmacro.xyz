## Executive conclusion

The repository cannot establish Adcash's internal reason for rejecting Site ID **1662562**. The supplied earnings figures ($26.98 total; $21.60 on 331 Adcash unique users) are owner-reported, not independently reconciled. $21.60 / 331 × 1,000 is approximately **$65.26 per 1,000 unique users**. That is not impression RPM, nor proof of invalid traffic.

**High-confidence code finding:** the deployed shared loader unconditionally initializes AutoTag on covered public pages. There was no default-off switch. It delegates execution to a mutable, remotely served third-party library. This is sufficient to permit provider-controlled click behavior; it does not identify the exact runtime handler responsible for the reported first click.

**First-click causation boundary:** no first-party universal click hijacker or first-party `window.open` was found in the audited production source. Download feedback deliberately leaves the anchor default action intact (`src/download.js:13–30`). Core hash scrolling, menu closing, keyboard controls, strategy dialogs and form submits use scoped handlers. Their use of `preventDefault` is not by itself a defect. Adcash documents that AutoTag rotates pop-under, interstitial, in-page push and video-slider formats. The owner's report is consistent with these formats being involved, but a live before/after event trace was not captured. Do not claim that Adcash necessarily requires a second click, violates its own terms, or caused the traffic rejection.

## Fixes and safeguards

1. Fail-closed public configuration; missing, non-boolean, disabled, rejected or malformed config performs no provider initialization. Both boolean switches must be true. No URL/storage override.
2. Preserve official library and zone references; no rewriting third-party logic, anti-adblock, fraud evasion, traffic generation, ad interaction or new paid services.
3. Exclude forms, staff/API/internal routes, policies, Strategy Network and framed contexts. Retain one loader per public document and one initialization per load, including a callback guard.
4. Cache-version all loader references; Node serves config with revalidation. Preserve visuals, canonical tags, SEO, analytics code, direct downloads and routing. Generator keeps the same safe integration.
5. Block hidden files, dependencies, DB/test/script/evidence directories and server-source extensions in Node static responses. Add conservative referrer and device-permission headers. Existing application limits/auth remain; proxy forwarding trust is a documented deployment requirement. Do not impose blanket bot/geo blocking based on speculation.
6. Ignore inert evidence in Git and block it on the Node server. Static-host exclusions still require operator verification.
