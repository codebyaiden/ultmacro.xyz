# Poll Phase 1 Implementation Plan

**Goal:** A usable anonymous adaptive survey at /poll, per the user's Phase 1 specification.
**Architecture:** Existing static HTML/CSS/JS, Web API handlers, pg pool and SQL migrations. The server owns question validation, path pruning, cursor, revisions, and completion. HttpOnly random session cookies identify a response; only their SHA-256 hashes are stored.
**Constraints:** No new dependencies; no Phase 2/3 features; preserve existing functionality. Node >=20. No personal identity fields.

1. Write and run failing engine tests for validation, all conditional paths, dependent ranking, pruning, completion and ETA. Implement `poll-definition.mjs` and `poll-engine.mjs`; run the tests.
2. Write failing handler tests for start/resume, save/navigation, authorization, revisions, malformed/oversized payloads and completion. Add `poll-store.mjs`, `poll.mjs`, migration 005, and the server route/body cap. Verify transaction behavior using PostgreSQL if available.
3. Add `poll/index.html`, `styles/poll.css`, `src/poll.js`: semantic one-question screens, debounced save queue, retryable errors, Back, ranking buttons, adaptive progress, completion. Check browser behavior at phone/tablet/desktop sizes and reduced motion.
4. Run the full npm suite, review the diff, document deployment and limitations, and save the isolated branch to GitHub.

Review focus: racing saves from tabs; answer edits removing dependent rankings; refresh before Continue; lost network responses; attempts to select another response via URL/body. All are covered by revisions, sequential saves, validation, and focused tests.

Ruling: the user's detailed spec and explicit instruction to summarize then implement supersede additional approval gates. Work stays on an isolated feature branch; production deployment configuration must be verified before a live rollout.

Execution record:
- Engine tests written before implementation; adaptive validation, pruning and ETA verified.
- Handler tests written before implementation; anonymous access, revisions, malformed inputs, start/save/resume/submit verified.
- SQL integration verified with external PGlite tooling; native PostgreSQL installation was unavailable. The runtime dependency list remains unchanged.
- Independent focused review found optional JSON null conversion and frontend save races. Optional Skip failed the SQL regression before COALESCE fixed it. Both frontend regressions failed with their fixes removed, then passed with fixes restored.
- Full suite: 33 passed, 0 skipped with SQL integration enabled. Browser flows checked at 320/390/820/1440px, plus offline/close/in-flight recovery and keyboard focus.
- Production configuration/access is unavailable in the exposed tools; deployment handoff is documented in POLL_PHASE1.md. Work is saved on a feature branch for review, without merging or modifying production.
